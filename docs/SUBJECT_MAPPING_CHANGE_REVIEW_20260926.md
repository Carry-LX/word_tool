# 学科映射变更复核

## 结论

本次软科 2026 数据接入不应改变既有学科映射关系。曾尝试将 `1251 工商管理`、`1252 公共管理`、`1254 旅游管理` 提升为软科确定性映射，复核原始映射表后确认该调整证据不足，现已全部撤回。

## 证据链

权威源文件为 `data/教育部学科与四大国际学科排名映射关系.xlsx`。

在“学科映射关系”工作表中：

- Excel 第 156 行：`1202 工商管理学` 对应软科“工商管理”。
- Excel 第 158 行：`1204 公共管理学` 对应软科“公共管理”。
- Excel 第 160 行：`1251 工商管理` 的软科对应列为空。
- Excel 第 161 行：`1252 公共管理` 的软科对应列为空。
- Excel 第 163 行：`1254 旅游管理` 的软科对应列为空。

在“Sheet1”反向映射表中：

- Excel 第 48 行：软科“工商管理”对应“工商管理学”。
- Excel 第 51 行：软科“公共管理”对应“公共管理学”。
- Excel 第 52 行：软科“旅游休闲管理”对应“工商管理学”。

两个工作表相互印证：软科排名学科对应的是学术学位一级学科，不应仅凭中文名称接近而迁移到 `125x` 专业学位代码。

但两个工作表的证据强度并不相同。项目原有逻辑以“学科映射关系”的正向列为准，只有反向表别名与正向列交集一致时才纳入 `mapping_sheet1`。因此“旅游休闲管理 → 工商管理学”只作为反向线索保留，不能越过主表中 `1202 → 工商管理` 的边界自动进入报告。

## 为什么原有留空是合理设计

项目的一级学科维度同时包含学术学位代码和专业学位代码。名称相近不等于排名口径相同：

1. 原始映射表已经显式区分 `1202 工商管理学` 与 `1251 工商管理`。
2. 软科“工商管理”在反向映射表中只指向 `1202`。
3. 如果把同一软科学科同时确定性映射到 `1202` 和 `1251`，会产生一对多桥接，并让专业学位报告看起来拥有并不存在的直接排名口径。
4. `manual_subject_aliases.json` 中没有 `mapping_class` 的历史规则不会被运行时当作确定性候选，这种“保留匹配线索但不自动选择”的设计应继续保留。

## 后续映射变更闸门

新增或提升为 `deterministic` 前，至少满足以下条件：

1. 主映射表或反向映射表存在明确对应关系。
2. 学位类型、一级学科范围和榜单口径一致。
3. 不会与已有确定性映射制造未经说明的一对多关系。
4. 目标学科在新排名数据中确有对应记录；“有数据”只能用于验证，不能替代映射证据。
5. 修改后同时检查综合排名、分项指标和 Word 展示口径，三者必须复用同一运行时选择。

本次接入保留的代码改动只包括新软科文件选择、工作表结构校验、数据重建和指标历史按已选学科精确过滤，不改变原有映射表定义。

## 下游防回流复核

全量生成前的跨学科抽检发现，`0803 光学工程` 的运行时来源决策已经将软科和 QS 判定为 `missing`，但两个汇总图仍可能从历史手工别名中重新读入“仪器科学”和“物理与天文学”。这不是映射表定义错误，而是下游工件构建器绕过了运行时选择结果。

现已统一规则：

1. 只要本次运行已经生成来源选择结果，该结果就是下游图表和指标筛选的唯一入口。
2. 已选学科为空时直接返回空数据，不再回落到历史候选别名。
3. 学科工件审计读取 `ranking_availability.csv`，凡 `selection_mode=missing` 的榜单，若重新出现在图表主数据或 `source_trace.csv` 中，审计直接失败。
4. 仅在旧运行没有来源选择结果时，才保留历史候选逻辑作为兼容兜底。

修复后重新生成光学工程：18/18 个数据工件通过审计，软科与 QS 均保持阻断。随后生成全部 46 个学科报告，42 份为完整分析报告，4 份因四榜均无可靠映射而生成覆盖说明；全量学科工件审计失败数为 0。
